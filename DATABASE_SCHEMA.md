# TravelEase Database Schema Documentation

This document outlines the complete database schema for the TravelEase application, which uses Convex as its backend database.

## Overview

The TravelEase application currently uses a single primary table (`trips`) to store all trip-related information. User data is stored within trip records rather than in a separate users table.

## Tables

### 1. trips

The main table storing all trip information generated by users.

#### Fields

| Field | Type | Description |
|-------|------|-------------|
| `_id` | `Id<"trips">` | Auto-generated unique identifier for each trip |
| `userSelection` | `object` | User input from the trip creation form |
| `userSelection.location` | `object` | Selected destination |
| `userSelection.location.label` | `string` | Name/label of the destination |
| `userSelection.travelers` | `number \| null` | Number of travelers |
| `userSelection.days` | `string` | Duration of the trip |
| `userSelection.budget` | `number \| null` | Budget level |
| `userSelection.numberOfMembers` | `number (optional)` | Alternative field for number of members |
| `userSelection.startDate` | `string (optional)` | Planned start date of the trip |
| `tripData` | `any` | AI-generated trip itinerary and details |
| `userEmail` | `string (optional)` | Email of the user who created the trip |
| `userId` | `string (optional)` | Unique identifier of the user who created the trip |
| `userInformation` | `object (optional)` | Comprehensive user information for analytics |
| `userInformation.userId` | `string` | User's unique identifier |
| `userInformation.userEmail` | `string` | User's email address |
| `userInformation.timestamp` | `number` | Timestamp when the trip was created |
| `userInformation.userAgent` | `string` | Browser/user agent information |
| `createdAt` | `number` | Unix timestamp of when the trip was created |
| `updatedAt` | `number (optional)` | Unix timestamp of when the trip was last updated |
| `shareId` | `string (optional)` | Unique identifier for sharing the trip |

#### Indexes

| Index Name | Fields | Description |
|------------|--------|-------------|
| `by_user` | `["userId"]` | Index to efficiently query trips by user ID |

## Functions

### Mutations

1. **saveTrip**
   - Creates a new trip record in the database
   - Generates a unique share ID for the trip
   - Stores all user selections and AI-generated trip data

2. **updateTripShareId**
   - Updates the share ID for an existing trip
   - Used when generating shareable links for trips

3. **updateTrip**
   - Updates an existing trip with new information
   - Updates the `updatedAt` timestamp
   - Allows users to modify their trip details

### Queries

1. **getTripsByUserId**
   - Retrieves all trips associated with a specific user ID
   - Uses the `by_user` index for efficient querying

2. **getAllTrips**
   - Retrieves all trips in the database, ordered by creation date (descending)

3. **getTripById**
   - Retrieves a specific trip by its unique ID

4. **getTripByShareId**
   - Retrieves a trip using its share ID for public viewing

## Data Flow

1. User creates a trip through the application interface
2. Form data is collected and sent to the AI for itinerary generation
3. Both user selections and AI-generated data are stored via the `saveTrip` mutation
4. Trips can be retrieved using various query functions
5. Users can update their trips using the `updateTrip` mutation
6. Trips can be shared using the `updateTripShareId` mutation and `getTripByShareId` query

## Security Considerations

- User data is associated with authenticated users when available
- Sensitive information like email addresses is stored only when necessary
- Data is indexed for efficient querying while maintaining privacy
- All data operations are performed through secure Convex functions

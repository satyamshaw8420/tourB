# TravelEase Application Features and Database Schema

This document provides a comprehensive overview of all implemented features in the TravelEase application and how they relate to the database schema.

## Core Features

### 1. AI-Powered Trip Planning
- Users input travel preferences (destination, duration, travelers, budget)
- AI generates detailed itineraries using Google Generative AI
- Trip data is stored in the Convex database

### 2. Trip Management
- Users can view their trip history
- Trips are associated with user accounts when authenticated
- Trips can be shared with others via unique share IDs

### 3. Interactive Maps
- Hotel locations displayed using OpenStreetMap integration
- Interactive maps showing points of interest
- Geo-coordinates stored with hotel data

### 4. Edit Trip Functionality
- Users can modify their trip details after creation
- Changes are persisted to the database with timestamps
- Form validation ensures data integrity

### 5. Responsive UI/UX
- Mobile-friendly design using Tailwind CSS
- Flexbox-based layout for itinerary presentation
- Modern, intuitive user interface

## Database Schema

### Primary Table: trips

The `trips` table stores all trip-related information:

#### User Selection Data
- `location.label` - Destination name
- `travelers` - Number of travelers
- `days` - Trip duration
- `budget` - Budget level
- `numberOfMembers` - Alternative traveler count field
- `startDate` - Planned start date

#### Generated Trip Data
- `tripData` - Complete AI-generated itinerary (hotels, activities, etc.)

#### User Association
- `userEmail` - User's email address
- `userId` - User's unique identifier
- `userInformation` - Comprehensive user data for analytics

#### Metadata
- `createdAt` - Creation timestamp
- `updatedAt` - Last modification timestamp
- `shareId` - Unique identifier for sharing trips

## Feature-to-Schema Mapping

### Trip Creation and Storage
When a user creates a trip:
1. Form data is collected in the `userSelection` object
2. AI generates itinerary stored in `tripData`
3. User information is captured in `userInformation`
4. Record is timestamped with `createdAt`
5. Unique `_id` is auto-generated by Convex

### Trip Editing
When a user edits a trip:
1. Modified data updates the `userSelection` object
2. Any changes to itinerary update `tripData`
3. `updatedAt` timestamp is added/updated
4. Changes are persisted through the `updateTrip` mutation

### Trip Sharing
When a user shares a trip:
1. A unique `shareId` is generated via `updateTripShareId` mutation
2. Others can view the trip using `getTripByShareId` query
3. Shared trips do not require authentication to view

### User Trip History
When a user views their trip history:
1. All trips associated with their `userId` are retrieved
2. Uses the `by_user` index for efficient querying
3. Trips are sorted by creation date (newest first)

## Data Flow

1. **Trip Creation**
   ```
   User Form → AI Generation → saveTrip Mutation → trips Table
   ```

2. **Trip Viewing**
   ```
   trips Table → getTripById/getTripsByUserId Queries → UI Display
   ```

3. **Trip Editing**
   ```
   UI Edits → updateTrip Mutation → trips Table Update
   ```

4. **Trip Sharing**
   ```
   Share Request → updateTripShareId Mutation → Share Link → 
   getTripByShareId Query → Public View
   ```

## Security and Privacy

- User data is only stored when users are authenticated
- Email addresses are stored only when provided
- Share IDs are randomly generated for security
- All database operations use Convex's secure function system
- Analytics data collection is opt-in through `userInformation`

## Scalability Considerations

- Index on `userId` enables efficient user-specific queries
- Flexible `tripData` field accommodates varying AI output formats
- Optional fields allow for schema evolution without migration
- Share ID system enables public trip viewing without authentication
